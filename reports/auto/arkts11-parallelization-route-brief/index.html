结论先行：可行性已经证明，收益尚未验证。

Native 能否替代 legacy 产出同样结果 —— 已证明（strict 诊断、emit 产物两项完成）；Native 内部并行是否有效、能否被 Node 主链遮蔽 —— 已证明。

替换后端到端快多少、内存涨多少 —— 两项均未知，因为至今没有删除任何 legacy 工作。E1 是从"可行"跨到"有收益"的第一步。

一句话读表：能替换的已经证明能替换，但"已删除"一列全是 ✕，所以端到端收益为 0。

当前 Native 的 378.8 ms 全部是额外成本（双跑 +2.66%）。E1 是第一次真正删除 legacy 工作的实验，也是收益能否成立的第一个决定性验证。

表中「等价性验证」为 L2 口径 —— 产物与诊断按稳定身份逐项比对（运行时 AST、es2abc 函数体、SourceMap 逐段解码、TP/FP/FN），只证明可以替换，不证明替换后有多快；真实收益须由同一 Hvigor clean 构建内 control / shadow / consume / skip 交错的 L3 实验给出，当前只做到 shadow。Linter 三项子耗时取自 ArkTSLinterTimePrinter 那轮（CompileArkTS 16,502 ms），占比为近似。禁止把 legacy 全链 18,806 ms ÷ Native 影子 365 ms 当作加速比。

「毛收益」不等于净收益。它只是阶段耗时上限，实际还要扣掉 Native 未被 Node 主链遮蔽的尾部。E1 另有一项特殊风险：strict 与 non-strict 共享惰性类型缓存，strict 一旦关闭，原本由它承担的部分共享成本会转移到 non-strict，净收益可能明显小于 470 ms。

因此建议以「Trace 中 strict 阶段是否真的消失」作为 E1 的成败判据，而不是以 2.5% 这个数字作为路线存废依据。
